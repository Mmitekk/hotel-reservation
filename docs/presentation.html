Что это такое

Модуль добавляет на сайт отеля всё, что нужно для приёма бронирований: форму поиска свободных номеров, корзину-заявку, панели управления и письма. Никаких сторонних сервисов бронирования — всё живёт внутри Drupal и вашей базы данных.

🛏️

Номера и цены

Сущности «Номер» и «Тип номера», превью и галереи через Media Library, цены по датам календаря, сезоны и скидки.

📝

Бронирование

AJAX-форма на сайте: проверка занятости, точный фильтр по вместимости, расчёт цены по ночам, защита от двойных броней.

✉️

Письма

Шаблоны писем редактируются в настройках: уведомление админу, подтверждение гостю, письмо о подтверждении брони. Почта никогда не ломает бронь.

📊

Панель и аналитика

Дашборд со статистикой и загрузкой, аналитика по выручке и конверсии, календарь занятости по месяцам.

👤

Гости и аккаунты

Аккаунт гостя создаётся автоматически при брони, вход по телефону, автовход после заявки, личный кабинет «Мои бронирования».

🔐

Роли и безопасность

Три роли с чёткими границами прав. Токены только для новых аккаунтов, CSRF на все действия, гости не видят админку.

Три роли — три мира

👑 Администратор

Полный контроль: настройки модуля, номера и типы, цены по датам, все брони, письма, экспорт CSV. Право administer hotel reservation — только доверенным людям.

🏢 Владелец отеля

Операционная работа без настроек: панель, аналитика, календарь, список броней, создание/редактирование/удаление броней, смена статусов, экспорт. Настройки, номера и цены — закрыты.

🧳 Клиент (гость)

Никакой админки и тулбара. Только сайт + личный кабинет «Мои бронирования»: свои брони, статусы, суммы. Аккаунт создаётся сам при первой брони.

Как проходит бронирование

1Поискгость выбирает даты и гостей на сайте
2НомерAJAX показывает свободные, карточка-модалка, сравнение
3Заявкаимя, телефон, email — цена считается по ночам
4Аккаунтсоздаётся автоматически, гость сразу входит в кабинет
5Статусотель подтверждает, заселяет, выселяет
Письма (админу и гостю) отправляются на каждом шаге, но сбой почты никогда не ломает бронирование — ошибка уходит в журнал, заявка сохраняется.

Жизненный цикл брони

Ожидает→ Подтверждено→ Заселён→ Выселён
Ожидает→ Отменено — номер снова свободен; запись остаётся в истории

Отменить — сменить статус, сохранив запись. Удалить — стереть навсегда. Занятость номера блокируют только статусы «Ожидает», «Подтверждено» и «Заселён». Цены считаются по календарю: обычная цена + сезонные надбавки/скидки по датам.

Администратор

Страницы

  • Панель /admin/hotel-reservation/dashboard — статистика, ожидающие брони, заезды недели, выручка за 7 дней
  • Бронирования …/reservations — таблица с фильтрами (статус, даты, номер), сортировкой, экспортом CSV, добавлением брони вручную
  • Календарь …/calendar — занятость по номерам на месяц, бейджи статусов, «сегодня» подсвечен
  • Аналитика …/analytics — KPI, конверсия, выручка по номерам, средний чек
  • Номера и типы, цены по датам — полноценный CRUD + календарь цен
  • Настройки …/settings — отель, валюта, сроки, письма, модалка, кнопка сброса кэша

Особенности

  • Действия над бронью — аккуратным списком: иконка + текст (изменить, удалить, подтвердить, отменить, заселить, выселить)
  • Просмотр брони — карточка-ваучер с печатью-friendly вёрсткой
  • Экспорт CSV с сохранением активных фильтров
  • Настройки не ломают роли: сохранение формы снимает лишние админ-права у ролей модуля

Владелец отеля

Работает с фронт-темы сайта, без тулбара и админ-меню. Навигация — фиксированное меню справа: Панель, Бронирования, Добавить бронь, Календарь, Аналитика + Профиль, Редактирование, Выход.

Может

  • Видеть статистику, аналитику и календарь занятости
  • Смотреть список броней с фильтрами, экспортировать CSV
  • Создавать брони вручную (телефонный заказ), редактировать и удалять
  • Менять статусы: подтвердить, отменить, заселить, выселить

Не может

  • Менять настройки модуля и письма
  • Управлять номерами, типами и ценами
  • Видеть тулбар и другие разделы админки ядра

Клиент (гость)

Как это работает

  • При первой брони аккаунт создаётся автоматически: логин — телефон, роль «Клиент отеля»
  • Сразу после заявки гость автоматически входит и попадает в кабинет, может задать пароль по одноразовой ссылке (24 часа, один раз)
  • Повторные брони привязываются по email или нормализованному телефону — дублей аккаунтов нет

Личный кабинет

  • /hotel-reservation/my-bookings — карточки броней: номер, фото, даты, статус, сумма, удобства
  • Видит только свои брони (по uid, email и телефону)
  • Фиксированное меню справа на всех страницах сайта: кабинет, профиль, редактирование, выход
  • Ни тулбара, ни админ-страниц, ни чужих данных

Технически

Установка

composer require mmitekk/hotel-reservation:^1.27
drush updatedb -y   # или /update.php
drush cr

Требования: Drupal ^9.5 || ^10, PHP ≥ 7.4, модули media и media_library. Сущности: hr_room, hr_room_type, hr_reservation, hr_room_pricing.

Публичный JSON API

  • GET /api/hotel-reservation/check-availability
  • POST /api/hotel-reservation/submit
  • GET /api/hotel-reservation/room/{id}
  • GET /api/hotel-reservation/room-prices/{id}
  • POST /api/hotel-reservation/set-password

Ответы всегда валидный JSON; сбои почты/токенов — только в журнал.

Безопасность

  • CSRF-токены на смены статусов
  • Одноразовые токены пароля — только новым аккаунтам, 24 ч, хранится только хэш
  • Автовход — только анониму и только свежесозданному аккаунту
  • Гостевые роли не имеют админ-прав; страницы владельца открыты только по гранулярным правам

Инфраструктура

  • Обновления — idемпотентные хуки update_100XX (роли, поля, бэкфилды)
  • Кнопка «Сбросить OPcache и пересобрать роуты» в настройках — для хостингов без drush
  • Репозиторий: github.com/Mmitekk/hotel-reservation, дистрибуция через Packagist
